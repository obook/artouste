# Configuration du simulateur Artouste (format "clé valeur", éditable à la main).
# Une clé et sa valeur par ligne ; une ligne commençant par # est un commentaire.
# Toute clé absente garde sa valeur par défaut.

# terrain : sous-dossier de assets/terrain/ à charger au lancement.
# Terrains disponibles :
#   ossau        vallée d'Ossau (lac d'Artouste, pic du Midi d'Ossau), montagne
#   cote-landes  côte landaise (Labenne -> Vieux-Boucau), bord de mer
#   arcachon     bassin d'Arcachon (Cap Ferret -> Marcheprime, Biscarrosse -> Arès), bord de mer
#   cauterets    Cauterets - Gavarnie (chemin des cascades, Pont d'Espagne, cirque de Gavarnie), montagne
#   bigorre      Pic du Midi de Bigorre (observatoire, col du Tourmalet, La Mongie), montagne
#   bordeaux     Bordeaux (la Garonne, port de la Lune, Mérignac, Pessac), terre intérieure
#   dax          Dax (Adour, arènes, aérodrome de Seyresse et musée de l'ALAT), terre intérieure
#   paris        Paris intra-muros (tour Eiffel, Notre-Dame, Montmartre), terre intérieure
#   dax-arene    Happy DeathHour, arène du mode zombie (lancement direct en combat)
# La variable d'environnement ARTOUSTE_TERRAIN, si définie, a la priorité.
terrain ossau

# turbine_demarree : 1 = turbine et rotor d'emblée au régime au lancement (au lieu
# de la séquence de démarrage d'environ une minute), pratique pour décoller tout de
# suite en test ; 0 = démarrage normal à froid. La variable d'environnement
# ARTOUSTE_TURBINE_DEMARREE, si définie, a la priorité.
turbine_demarree 0

# demo : 1 = mode démonstration automatique au lancement. L'appareil joue tout seul
# un vol (démarrage rapide, décollage, montée et vol jusqu'à la Dune du Pilat survolée
# vers 1500 m, demi-tour et retour se poser sur le pad de départ), rejoué en boucle ;
# le terrain est alors forcé sur arcachon. Une entrée du pilote sur le manche coupe
# la démo. La variable d'environnement ARTOUSTE_DEMO, si définie, a la priorité.
# 0 = pas de démo. (La démo se lance aussi par le bouton Démo du menu de démarrage.)
demo 0

# relief_fenetre : 1 = fenêtre de relief fin autour de l'appareil, qui redessine
# le sol au pas du LiDAR sur quelques kilomètres. 0 = éteinte (défaut) -- son
# raccord au relief lointain n'est pas encore au point, les crêtes se
# construisent à l'approche. Éteinte, ses tuiles ne sont même pas lues.
# La variable d'environnement ARTOUSTE_RELIEF l'allume, ARTOUSTE_NO_RELIEF
# l'éteint et l'emporte.
relief_fenetre 0

# relief_debug : 1 = liserets de diagnostic aux frontières de la fenêtre de
# relief -- contour du noyau en magenta, contour de l'anneau en cyan, début du
# fondu en orange et fin du fondu en jaune. Le terrain garde ses couleurs
# partout ailleurs, ce qui rend le mode utilisable en vol. 0 = rendu normal
# (défaut). Sans effet si relief_fenetre vaut 0 : il n'y a alors aucune
# frontière à tracer.
relief_debug 0

# arbres : 1 = végétation activée (défaut) -- des arbres en billboards sont semés
# d'après l'orthophoto, là où le sol est vert et sous la limite forestière. Ce
# n'est pas réservé à la montagne : une ville entourée de bois en reçoit aussi.
# 0 = pas d'arbres, rendu plus léger, utile sur une machine modeste (ex. tablette :
# 30-50 fps avec les arbres contre 60 fps sans) ; voir aussi "arbres_max" plus bas,
# qui les éclaircit sans les supprimer.
#
# Cette clé ne décide que pour les cartes qui ne disent rien : le gestionnaire de
# cartes (touche C au menu) permet de trancher carte par carte, ce qui laisse les
# arbres en montagne et les évite en ville. La variable d'environnement
# ARTOUSTE_NO_TREES, si définie, force la désactivation quelle que soit cette clé.
arbres 1

# zone_hv : 1 = le HUD affiche ZONE H-V quand l'appareil se trouve dans le domaine
# hauteur-vitesse d'où une autorotation réussie n'est pas garantie en cas de panne
# (diagramme du manuel de vol). 0 = pas d'indication (défaut) : l'appareil d'époque
# n'avertit de rien, et le domaine couvre tout stationnaire entre 2 et 150 m sol,
# donc l'indication resterait allumée une bonne partie du vol.
zone_hv 0

# verifier_maj : 1 = recherche d'une mise à jour au lancement (défaut). Le
# simulateur demande, dans un fil séparé qui ne retarde rien, le numéro de la
# dernière version publiée. S'il y en a une plus récente que la vôtre, le menu de
# démarrage l'annonce en bas et propose de l'aller chercher sur la page du
# projet, https://obook.github.io/artouste/ (bouton Télécharger, ou touche M, qui
# ouvre votre navigateur). Rien n'est envoyé : c'est une simple lecture, sans
# identifiant ni statistique, et le vol part sans rien attendre du réseau.
# 0 = ne rien demander au réseau au lancement. La variable d'environnement
# ARTOUSTE_NO_MAJ, si définie, coupe la recherche quelle que soit cette clé.
verifier_maj 1

# radio_url : URL d'un flux radio internet (MP3 sur HTTP) joué dans le cockpit.
# Touche K en vol libre pour l'allumer ou la couper. Vide = pas de radio.
# La variable d'environnement ARTOUSTE_RADIO_URL, si définie, a la priorité.
# Exemple (décommenter pour activer) :
radio_url https://stream2.madein80.live/listen/madein80/playhd.mp3

# soleil_vitesse : vitesse d'écoulement du temps pour le cycle jour/nuit (course du
# soleil). Durée réelle d'une journée complète = 86400 / soleil_vitesse secondes.
#   1   = temps réel : départ à l'heure locale du PC
#   72  = journée complète en 20 min (défaut)
#   144 = journée complète en 10 min
#   0   = temps figé à 8h du matin (le soleil ne bouge pas)
# En temps réel (1) le soleil part de l'heure locale du PC ; pour toute autre valeur il
# part de 8h du matin, pour démarrer sur une belle lumière. Avec 0, il reste figé à 8h.
soleil_vitesse 72

# lune_vitesse : multiplicateur de la vitesse ci-dessus pendant la nuit, du coucher
# (18 h) au lever (6 h). Voler une demi-journée dans le noir n'apporte pas
# grand-chose, alors qu'un ciel qui bascule du crépuscule à l'aube pendant qu'on
# rentre, si.
#   2 = la nuit passe deux fois plus vite que le jour (défaut)
#   1 = nuit et jour à la même vitesse
#   4 = nuit expédiée
# Avec les valeurs par défaut (soleil_vitesse 72, lune_vitesse 2), un cycle complet
# dure un quart d'heure : dix minutes de jour et cinq de nuit. Sans effet quand le
# temps est figé (soleil_vitesse 0).
lune_vitesse 2

# brume_debut / brume_fin : distances, en mètres, où le terrain commence à se
# fondre dans la teinte du ciel et où il y disparaît tout à fait. La brume donne
# la profondeur et masque le bord du terrain.
#   3000 / 15000 = valeurs par défaut, essayées en vol
#   monter les deux = air plus limpide, lointain plus net, mais le bord des
#     petites cartes (Dax fait 6 km de côté) se voit à l'horizon
#   descendre les deux = temps bouché ; attention, trop bas, une petite carte
#     entière vire au blanc vue d'en haut et les sommets d'une carte de montagne
#     s'effacent
brume_debut 3000
brume_fin 15000

# ----------------------------------------------------------------------------
# Performances (utile sur GPU intégré ou tablette : plus la charge est basse,
# plus la cadence est élevée et moins la machine chauffe).
# ----------------------------------------------------------------------------

# arbres_max : budget de végétation (nombre maximum d'arbres soumis au GPU). Au-delà,
# le semis est éclairci uniformément. C'est le poste de rendu le plus coûteux quand
# les arbres sont actifs (voir la clé "arbres"). Défaut 1600000 ; descendez vers
# 500000, voire 300000, sur une machine modeste. Sans effet si "arbres 0".
# La variable d'environnement ARTOUSTE_TREE_MAX, si définie, a la priorité.
arbres_max 1600000

# msaa : anti-crénelage (échantillons par pixel). 4 (défaut) lisse bien les contours ;
# 2 allège la bande passante mémoire (différence peu visible en 1080p) ; 0 le désactive
# (le plus rapide). La variable d'environnement ARTOUSTE_MSAA, si définie, a la priorité.
msaa 4

# tuiles_dossier : dossier où sont rangés les jeux de tuiles de détail, un
# sous-dossier par carte. Par défaut "assets/terrain", c'est-à-dire chaque carte
# chez elle, dans son sous-dossier "tuiles" : rien à changer si vous les laissez
# où le jeu les a fabriquées.
#
# Une carte fine pèse jusqu'à deux gigaoctets : indiquez ici un chemin absolu
# pour les garder sur un autre disque, sans quoi elles remplissent le disque
# système.
#   Linux   : tuiles_dossier /media/moi/DISQUE/artouste-tuiles
#   Windows : tuiles_dossier D:/artouste-tuiles
# Un chemin relatif est compris depuis le dossier du jeu. La variable
# d'environnement ARTOUSTE_TUILES, si définie, a la priorité (pratique pour
# essayer un autre disque le temps d'un lancement).
tuiles_dossier assets/terrain

# relief_sommets_max : nombre maximum de points de la carte d'altitude
# effectivement DESSINÉS. Au-delà, le maillage n'en retient qu'un sur deux, sur
# trois... Les altitudes restent lues en entier pour poser l'appareil, porter les
# hélisurfaces et la collision : une carte au relief fin améliore donc le vol
# même sur une machine qui ne peut pas tout dessiner.
#   1200000 = maillage des cartes actuelles (défaut)
#   300000  = machine modeste ou tablette
#   0       = tout dessiner (une carte en grille 2048 fait alors 4,2 millions de
#             sommets et 8,4 millions de triangles par image)
# La variable d'environnement ARTOUSTE_RELIEF_SOMMETS, si définie, a la priorité.
relief_sommets_max 1200000

# tuiles_fenetre_px : côté, en pixels, de la fenêtre d'orthophoto fine entretenue
# autour de l'appareil sur les cartes qui livrent un jeu de tuiles (dossier
# "tuiles", voir docs/CARTES.md). Le sol proche y passe de plusieurs mètres par
# pixel à moins d'un mètre, pour une occupation de mémoire vidéo constante, quelle
# que soit la taille de la carte.
#   8192  = 89 Mo de mémoire vidéo, détail jusqu'à 0,9 km (défaut)
#   16384 = 356 Mo, détail jusqu'à 1,8 km (grosse carte graphique)
#   4096  = 22 Mo, détail jusqu'à 0,5 km (machine à faible mémoire vidéo)
#   0     = pas de détail fin (l'orthophoto d'ensemble seule, comme avant)
# Rayons donnés pour des tuiles à 0,25 m/px, la finesse que fabrique le
# gestionnaire de cartes ; ils doublent sur un jeu à 0,50 m/px.
# Sans effet sur une carte sans tuiles. La variable d'environnement
# ARTOUSTE_TUILES_FENETRE, si définie, a la priorité ; ARTOUSTE_TUILES désigne un
# dossier de tuiles hors du jeu (un sous-dossier par carte).
tuiles_fenetre_px 8192
